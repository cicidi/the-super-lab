Pipeline

The five artifacts that carry a problem from requirement to regression-safe verification: PRD → decision history → spec → impl plan → test plan.

01 · Requirement

The pipeline inherits the parent requirement: define the problem, record decisions before acting, start design when decisions are settled enough, order the implementation, and make the test plan catch regressions. Its own requirement is one rule: the five artifacts are produced in order, by cooperating skills, and no later stage silently rewrites an earlier artifact.

02 · Design

D1

PRD

Every later decision is checked against it. A requirement/decision conflict is resolved by a human.

D2

Decision history

Append-only; a superseded decision stays and a new entry supersedes it. AI drafts; human confirms.

D3

Spec

Starts when decisions are settled or settled enough; names the open ones. HLD/LLD split deferred.

D4

Impl plan

Sequence, task detail, and preparation.

D5

Test plan

Completion check plus regression guard.

D6–D8

Cooperation

Read the previous artifact; no silent rewrite; human adjudication; lineage and supersede.

The core rule

A later stage that disagrees with an earlier artifact reports the conflict and asks. It never silently rewrites the earlier artifact.

03 · Impl

This sub-feature has no standalone impl plan. The pipeline is implemented by the skills that own each stage; the concrete skill names are out of scope for this spec.

Where impl lives

Pipeline stages are implemented by the SDD skills (spec-organize, spec-review, spec-write). Concrete skill bodies live under skills/, not in this docs tree.

04 · Verify

Verification is at the artifact boundaries, not by reading the skills:

  • PRD contains the six required inputs; a decision can cite the section it relies on.
  • Decision history is append-only; every product-direction decision has an entry.
  • Spec names the decisions it depends on and any still open.
  • Impl plan is ordered and each task names its preparation.
  • Test plan has a completion check and a regression guard.
  • A test can be traced back to the requirement it verifies.
