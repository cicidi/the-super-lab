Spec-Driven Development — 实现计划

本篇列出把 SDD 做出来的任务和先后顺序。每个任务写明依赖哪个任务、挡住了哪个任务、做到什么程度算完成（document-standard 的 DSGN-E）。术语见 parent design 的术语表。

Global Constraints

  • 先改 spec，再改 skill： 做任务时发现 spec 有错，先问人，改好 spec，再改 skill 和测试。
  • skill 的写法： SKILL.md 用 skill create 或 skill edit（见 skills/skill/SKILL.md）来写。本篇只规定顺序。
  • 测试： 测什么见 test-plan，测试文件放在 skills/spec-organize/tests/。
  • 不做 wayfinder-import sub-feature（ARD-T）。
  • 评测： 用 deepseek-flash 生成 gold 跑 3 次、复核跑 5 次；跑分结果和报告不提交，复核结论文件 judgments/ 要提交（ARD-CJ）。打分用 iPhone 案例（ARD-BL）。
  • 不迁移旧文档，只修 SDD 自己这套（ARD-CK，重述 ARD-AF）。
