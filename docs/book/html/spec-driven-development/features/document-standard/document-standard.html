Document Standard

The rules that keep every feature's PRD, design, plans, tests, and decision history consistent: authority by concern, content priority, health, naming, document types, and four enforcement modes.

01 · Requirement

Every feature produces five kinds of documents; a repository produces many features. Without one standard, four failures follow: no artifact wins a conflict; documents sprawl and cannot be found; a stale spec is indistinguishable from a wrong one; and the same fact is maintained in several places.

The requirement is one rule: each fact has one authoritative home, and every document is placed, named, and checked the same way.

02 · Design

D1 · AUTH

Authority by concern

Intended behavior → spec; current implementation → code; contracts → machine artifact; schema → migrations; verification → tests. Conflicts are reported, not silently resolved.

D2 · SCOPE

Scope and size

Behavior over implementation. A spec describes contracts, invariants, constraints, and boundaries; not class structure. 1,000-line cap; split on a boundary.

D3 · HEALTH

Health and drift

Metadata, health not status, stale ≠ wrong; drift detection; detect → report → ask; change checklist; no duplicated fact.

D4 · PRIO

Content priority

L1 decisive, L2 rationale, L3 alternatives, L4 support. L1 is never deleted; trim L4, then L3, compress L2, split if still long.

D5 · NAME

Paths and naming

docs/features/<feature>/<type>/<feature>-<type>.md; aspect nouns for spec parts; numbered phases for plans; collision signals.

D6 · STD

Document types

Six committed types plus gitignored state; frontmatter; required sections; decision history; Change Log; scratch; INDEX; PROTECTED.

D7 · MODE

Enforcement

Organize, Lint, Consolidate, Sync — what each does and what it refuses to do.

D8–D9

Gates and traceability

MUST/NICE checklists, anti-patterns, and the rule-group → implementing-file map.

The core rule

No fact is maintained twice. A second appearance is a link, not a restatement. When two artifacts disagree, detect → report → ask; never detect → guess → rewrite.

03 · Impl

The standard is implemented by the spec-organize skill. It is not a separate runtime; it is the operational text an agent loads, with four modes:

04 · Verify

Verification is Lint plus the quality gates:

  • Every document under docs/features/, with a valid type and filename.
  • Four frontmatter fields; final has final_date.
  • Required sections present; Change Log last and append-only.
  • Spec/impl-plan under 1,000 lines, or split on a boundary.
  • No fact maintained in two places; no silent conflict resolution.
  • INDEX regenerated after any create, move, rename, or delete.
